## 声明式编程与受控/非受控组件

### 声明式编程
声明式编程是一种编程范式，它描述"做什么"而不是"怎么做"。在React中，我们声明UI应该是什么样子，而不是手动操作DOM。

```jsx
// 声明式 - 描述状态
const [count, setCount] = useState(0);
return <div>{count}</div>

// 命令式 - 手动操作DOM
document.getElementById('counter').textContent = count;
```

### 受控组件 vs 非受控组件

**受控组件：**
- 表单数据由React状态管理
- 通过props传入值，通过onChange更新状态
- 数据流清晰，便于验证和控制

```jsx
function ControlledForm() {
  const [value, setValue] = useState('');
  
  return (
    <input 
      value={value}
      onChange={(e) => setValue(e.target.value)}
    />
  );
}
```

**非受控组件：**
- 表单数据由DOM自身管理
- 使用ref获取表单值
- 性能更好，但控制性较差

```jsx
function UncontrolledForm() {
  const inputRef = useRef();
  
  const handleSubmit = () => {
    console.log(inputRef.current.value);
  };
  
  return <input ref={inputRef} />;
}
```

## React类组件中的super(props)

### 为什么需要调用super(props)

在React类组件中，必须调用`super(props)`来初始化父类（React.Component）：

```jsx
class MyComponent extends React.Component {
  constructor(props) {
    super(props); // 必须调用，否则this.props为undefined
    this.state = { count: 0 };
  }
}
```

**原因：**
1. 调用父类构造函数，初始化组件实例
2. 将props绑定到this.props
3. 如果不调用super，this.props在constructor中为undefined

**注意：** 在React 17+中，如果不写constructor，React会自动调用super(props)。

## 原型继承 vs 类继承

### 原型继承

```javascript
function Animal(name) {
  this.name = name;
}

Animal.prototype.speak = function() {
  console.log(`${this.name} makes a sound`);
};

function Dog(name) {
  Animal.call(this, name);
}

// 设置原型链
Dog.prototype = Object.create(Animal.prototype);
Dog.prototype.constructor = Dog;

const dog = new Dog('Rex');
dog.speak(); // Rex makes a sound
console.log(dog instanceof Animal); // true
console.log(dog instanceof Dog); // true
```

### 类继承

```javascript
class Animal {
  constructor(name) {
    this.name = name;
  }
  
  speak() {
    console.log(`${this.name} makes a sound`);
  }
}

class Dog extends Animal {
  constructor(name) {
    super(name); // 必须调用父类构造函数
  }
}

const dog = new Dog('Rex');
dog.speak(); // Rex makes a sound
console.log(dog instanceof Animal); // true
console.log(dog instanceof Dog); // true
```

### instanceof行为

`instanceof`检查对象的原型链是否包含指定构造函数的prototype：

```javascript
// 原型链：dog -> Dog.prototype -> Animal.prototype -> Object.prototype
console.log(dog instanceof Dog); // true
console.log(dog instanceof Animal); // true
console.log(dog instanceof Object); // true
```

### 为什么类继承需要先实例化父类

1. **初始化父类状态**：父类可能有自己的初始化逻辑
2. **确保继承完整性**：子类需要父类的完整功能
3. **避免状态不一致**：防止父类状态未初始化导致的问题

## 基类构造函数 vs 派生类构造函数

### ES6中的区别

```javascript
class Base {
  constructor() {
    console.log('Base constructor');
    this.baseProp = 'base';
  }
}

class Derived extends Base {
  constructor() {
    super(); // 必须调用，且必须在访问this之前
    console.log('Derived constructor');
    this.derivedProp = 'derived';
  }
}

const obj = new Derived();
// 输出：
// Base constructor
// Derived constructor
```

**关键点：**
- 派生类构造函数必须调用super()
- super()必须在访问this之前调用
- 父类构造函数先执行，子类后执行

## 原型链继承原理

JavaScript的原型链继承基于以下机制：

```javascript
// 原型链查找过程
function findProperty(obj, prop) {
  while (obj !== null) {
    if (obj.hasOwnProperty(prop)) {
      return obj[prop];
    }
    obj = Object.getPrototypeOf(obj);
  }
  return undefined;
}

// 示例
const obj = {};
obj.__proto__ = { a: 1 };
obj.__proto__.__proto__ = { b: 2 };

console.log(findProperty(obj, 'a')); // 1
console.log(findProperty(obj, 'b')); // 2
```

## Ant Design Form组件实现

### 双向数据绑定实现

Ant Design的Form组件通过以下方式实现双向绑定：

```jsx
// 简化的实现原理
function Form({ children, form }) {
  const [values, setValues] = useState({});
  
  const setFieldValue = (name, value) => {
    setValues(prev => ({ ...prev, [name]: value }));
  };
  
  const getFieldValue = (name) => values[name];
  
  const contextValue = {
    setFieldValue,
    getFieldValue,
    values
  };
  
  return (
    <FormContext.Provider value={contextValue}>
      {children}
    </FormContext.Provider>
  );
}

function FormItem({ name, children }) {
  const { setFieldValue, getFieldValue } = useContext(FormContext);
  
  const handleChange = (value) => {
    setFieldValue(name, value);
  };
  
  return React.cloneElement(children, {
    value: getFieldValue(name),
    onChange: handleChange
  });
}
```

### onChange事件拦截

Form组件通过以下方式拦截onChange：

```jsx
// 事件拦截机制
function interceptOnChange(originalOnChange, formOnChange) {
  return (...args) => {
    // 先执行表单的onChange
    formOnChange(...args);
    // 再执行原始的onChange
    if (originalOnChange) {
      originalOnChange(...args);
    }
  };
}
```

## React合成事件

### 合成事件机制

React的合成事件是对原生DOM事件的封装：

```jsx
function handleClick(e) {
  // e是合成事件对象，不是原生DOM事件
  console.log(e.nativeEvent); // 原生事件
  console.log(e.target); // 事件目标
  console.log(e.currentTarget); // 当前处理事件的元素
}
```

### React 18中的变化

**React 17之前：**
- 事件委托到document
- 事件池化（已废弃）

**React 18：**
- 事件委托到root容器
- 移除事件池化
- 更好的并发支持

```jsx
// React 18中的事件处理
function App() {
  const handleClick = (e) => {
    // 不再需要e.persist()
    console.log(e.target);
  };
  
  return <button onClick={handleClick}>Click me</button>;
}
```

## JavaScript性能优化

### apply、call、bind的性能影响

```javascript
// 性能对比
const obj = { name: 'test' };
const func = function() { return this.name; };

// 直接调用 - 最快
func.call(obj);

// apply - 稍慢（需要处理参数数组）
func.apply(obj, []);

// bind - 最慢（创建新函数）
const boundFunc = func.bind(obj);
boundFunc();
```

**V8优化：**
- 内联缓存优化直接调用
- bind创建的函数需要额外的查找
- 频繁调用时性能差异明显
