# 栅格化（Rasterization）详细解析

## 一、什么是栅格化？
栅格化是浏览器渲染流程中的关键步骤，指的是将矢量图形（如 HTML 元素、CSS 样式、SVG、文字等）转换为位图（像素）的过程。最终生成的位图会被合成线程（Compositor）绘制到屏幕上。

---

## 二、栅格化的详细步骤

### 1. 生成 Display List（显示列表）
- 浏览器会将每个图层（Layer）的绘制指令（如绘制矩形、文字、图片、阴影等）整理成 Display List。
- Display List 是一组"要画什么"的指令集合，描述了每个 Layer 需要如何被绘制。

### 2. Tiling（切片）
- 每个 Layer 会被切分为多个小块（Tile），通常为 256x256 或 512x512 像素。
- 切片的目的是便于并行处理和只渲染可见区域。
- 滚动、动画时只需栅格化新出现的 Tile。

### 3. 分配栅格化任务到栅格化线程
- 主线程将每个 Layer 的 Tile 及其 Display List 提交给栅格化线程（通常是 GPU 进程或专用线程）。
- 多个 Tile 可以被多个线程并行处理。

### 4. 执行栅格化（Rasterization）
- 栅格化线程根据 Display List，将矢量指令转换为像素数据，生成位图（Bitmap）。
- 复杂的图形（如渐变、阴影、SVG、文字）都在此阶段被"画"成像素。
- 现代浏览器通常利用 GPU 加速栅格化过程，尤其是图片、渐变、抗锯齿等操作。

### 5. 生成位图缓存（Tile Cache）
- 栅格化后的 Tile 会被缓存，避免重复计算。
- 未变化的 Tile 可直接复用缓存，提升滚动和动画性能。

### 6. 合成（Compositing）
- 合成线程（Compositor Thread）将所有 Layer 的位图 Tile 合成为最终页面，显示在屏幕上。
- 合成时会处理层叠、透明、变换等效果。

---

## 三、栅格化与 GPU 的关系
- 现代浏览器会尽量将栅格化任务交给 GPU 处理，利用其强大的并行计算能力。
- GPU 擅长处理大规模像素运算，如图片解码、渐变、抗锯齿等。
- 但部分操作（如复杂矢量路径、某些字体渲染）仍可能在 CPU 上完成。

---

## 四、栅格化的优化点
- **只栅格化可见区域**：不可见部分不会被栅格化，节省资源。
- **并行栅格化**：多个 Tile 可在多线程/多核 CPU 或 GPU 上并行处理。
- **重用缓存**：未变化的 Tile 可直接复用，减少重复工作。
- **优先栅格化首屏内容**：提升首屏渲染速度和用户体验。

---

## 五、常见问题与挑战
- **频繁重绘**：频繁修改样式或动画会导致大量 Tile 失效，频繁栅格化，影响性能。
- **大面积透明/阴影/滤镜**：这些效果会增加栅格化计算量。
- **过多分层**：过多的 Layer 会增加栅格化和合成的负担。
- **GPU 资源有限**：GPU 显存有限，过多大图层或高分辨率 Tile 会导致内存压力。

---

## 七、总结
- 栅格化是将矢量绘制指令转为像素位图的过程，是浏览器渲染性能优化的关键环节。
- 主要步骤包括：Display List 生成 → Tiling → 并行栅格化 → 位图缓存 → 合成显示。
- 合理分层、减少重绘、优化动画和图片资源，有助于提升栅格化效率和页面性能。
